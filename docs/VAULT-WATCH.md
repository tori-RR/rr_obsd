# Vault Watch

Vault Watch 补充 Windows 原生文件通知，让直接打开在 SMB / NAS 上的仓库显示外部修改。笔记保留在原位置。

## 使用

安装完整的 `rr_obsd` 目录后，在整合插件设置里开启「原生文件监听」。每个启用该模块的已打开仓库运行一个隐藏的辅助进程。`native/watch.ps1` 是安装必需文件。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 原生文件监听 | 开启 | 启停当前仓库的监听和核对 |
| 状态栏 | 显示 | 显示监听、核对、等待连接等状态 |
| 合并变化的等待时间 | 200 ms | 合并重复事件，可调为 100–1000 ms |
| 活动笔记补查 | 5 秒 | 仅补查当前活动 Markdown 笔记，可调整，0 关闭 |
| 全库兜底检查 | 180 秒 | 上次扫描完成后等待该间隔再核对，可调整，0 关闭 |

命令面板提供「核对外部文件变化」「重启原生监听」「启用／暂停原生监听」。设置立即生效。

## 刷新时机

- 文件和目录事件触发相关路径核对；目录改名会覆盖其子树。
- 针对已打开文件的内容事件分别合并，避免两个文件的刷新相互取消。
- 默认每 5 秒补查当前活动 Markdown 笔记，以应对内容修改通知缺失。
- 全库安全核对默认在前一次安排的核对完成 180 秒后重新计时，只将元数据变化、消失或索引缺失的条目交给 Obsidian。
- 启动、断线恢复、通知溢出和手动命令执行强制核对。扫描中最多保留一个合并的后续请求。

两项间隔均可调整，设为 0 可关闭。活动笔记补查只针对当前活动笔记，不是全库扫描。网络不可用、读取或扫描较慢、宿主队列繁忙时，实际延迟会更长。周期核对使用元数据判断变化；保留原元数据的外部写入可能需要手动强制核对。

## 正在编辑时

插件只在确认编辑器仍对应同一文件、没有未保存输入、没有正在保存或读取期间新增的编辑时更新视图。外部修改与本地输入冲突时，保留当前输入并提示检查，不用磁盘内容强制覆盖。

收到提示后，先保留需要的本地内容，再比较磁盘版本并决定如何合并。Vault Watch 本身不提供版本合并、同步或备份；其他程序和 Obsidian 的自动保存仍可能写入文件。

## 平台和边界

- 原生监听仅支持 Windows，使用系统 Windows PowerShell 和 .NET，不需要下载原生 npm 模块或安装 SDK。
- 当前接口适配以 Obsidian 1.13.7 为基线。升级 Obsidian 后，应使用一次性测试笔记重新检查正文和目录刷新。
- 依赖实际 SMB 通知。Windows 客户端写入与 NAS 本机、Linux/NFS 写入需分别验证。
- 忽略以点开头的路径段，包括 `.obsidian`、`.git`；跳过 symlink、junction 及非普通文件/目录。
- 核对索引不改写源笔记。外部改名按原路径消失、新路径出现处理，不承诺自动重写笔记内的链接。
- 断线和权限错误不会被当作删除证据；失败的部分目录枚举不用于应用删除计划。
- 如果系统策略阻止 PowerShell 子进程或 `Add-Type`，模块无法启动；插件不修改这些策略。

## 排查与回滚

确认安装目录内存在 `native/watch.ps1`，再查看状态栏或设置页的状态。连接恢复后可运行「重启原生监听」；需要重新核对完整索引时使用「核对外部文件变化」。

只用已授权的临时笔记验证新增、改内容和重命名。记录写入来源、是否正在编辑及实际延迟；避免把共享可读或辅助进程存活当作通知已正确送达的证据。

升级前保留整个旧插件目录。回滚时停用 RR Obsd Toolbox，恢复备份，再启用；不要为修复刷新而删除仓库内容。具体测试记录见 [VALIDATION.md](VALIDATION.md)，开发细节见 [ARCHITECTURE.md](ARCHITECTURE.md)。
